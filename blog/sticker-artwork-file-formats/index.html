Sticker Artwork Files: Close Missing Dependencies Before Release

Updated October 22, 2026.

By ZC Labels · B2B procurement guide · Sources and editorial approach

In this guide
  1. Decide what the next person needs to do
  2. Distinguish vector content from raster content
  3. Check fonts and linked images before export
  4. Preserve the information that changes production
  5. Select the deliverable for the requested action
  6. Verify the handoff on the receiving side
  7. Close a receiving-side dependency record

The designer opens the source without a warning; the receiver sees a missing image. Before releasing sticker artwork files, connect the received source, its dependencies and the exact checked export. A familiar extension and a complete-looking preview are useful references, but they cannot close a missing or substituted asset by themselves.

Choose the handoff format according to what needs to remain editable and what must reproduce accurately. Keep an appearance reference alongside the appropriate source where available. A familiar extension is a useful label, not proof that fonts, images, dimensions and production information have survived the export.

Decide what the next person needs to do

Separate viewing, editing and production exchange. A visual reference helps communicate the intended appearance. An editable source may allow text, paths or layout to be adjusted. A production export must preserve the information required by the receiving workflow. One file can support several tasks, but do not assume it does.

Ask which format and settings the supplier needs before changing the only original. If a contour, white separation or specific effect requires an identified setup, obtain that instruction. Preserve a source copy so a later wording correction is still possible.

The artwork preparation guide organizes the overall handoff. This article addresses a narrower decision: whether the files retain what that handoff requires, rather than whether every project should use the same extension.

Distinguish vector content from raster content

Vector artwork represents shapes through paths. Raster artwork uses pixels. A document can contain both, and a vector-capable format can still contain an embedded low-detail raster image. Exporting that image into a PDF or AI document does not recreate the missing original geometry.

At final printed dimensions, inspect the content that matters: letters, curves, image detail and edges. Supply the highest-quality original available rather than a messaging preview. Enlarging a low-detail image or changing its resolution label does not restore information that was never present.

File roleWhat to checkWhat the extension cannot promise
Editable vector sourcePaths, text, effects and linked contentEvery object is actually vector or self-contained
Layered image sourcePixel detail and useful separated contentUnlimited enlargement or editable typography
Review or production PDFCorrect export, dimensions and preserved featuresIt matches the latest source or contains all special instructions
PNG or other image referencePixel dimensions, transparency and final-size detailAn editable cutline or production white separation

If only a raster original exists, send it honestly and explain the required dimensions. Ask what reconstruction or additional work would be needed, who would approve it and whether the result still represents the original design. Do not describe an automatic conversion as a verified reproduction.

Check fonts and linked images before export

Text can change when a required font is unavailable or substituted. Linked images can be absent even when the designer's local document looked complete. Ask the designer to review the package's dependencies and the receiving workflow's requirements.

Where appropriate, an outlined-text export can preserve letter shapes, but it changes how later text editing works. Keep the editable original and check the outlined export against it. Do not distribute font files unless the relevant permissions allow that handoff; the practical goal is reliable reproduction, not indiscriminate file collection.

Review the actual PDF or other export being sent. Compare the longest variant name, images and special print intent against the source reference. An export preset may help organize a workflow, but selecting it is not evidence that every object in the document is correct.

Preserve the information that changes production

Check transparency, effects and color handling relevant to the design. Adobe's PDF options describe settings that affect editability, fonts, transparency and overprinting. Their availability does not determine which settings a particular supplier requires. Agree that requirement instead of choosing an impressive preset name by habit.

White printing needs special care. A white-looking area in a preview is not automatically a defined print separation. The white-ink readability guide explains how to connect that intent to the actual background and critical text.

Cutting information has another role. An appearance image may show the desired contour without providing a usable path. Use the cutline guide to agree the finished edge and how cutting information should be delivered. Do not let a decorative outline become a cut instruction by accident.

Select the deliverable for the requested action

If the task is a wording or contour edit, ask for an appropriate editable original plus the reference appearance. If the artwork is photographic, retain the original pixel file rather than rebuilding it as nominal vector shapes. If the next step is review only, an identified checked export may be appropriate, with its limitations stated. Special white or cutting information still needs the receiving workflow's agreed representation. This decision starts from the requested action, then checks the file content; it does not rank extensions in isolation.

Verify the handoff on the receiving side

Request confirmation of any missing or changed content before approving the resulting proof. If a supplier modifies the file for production, review the affected appearance and geometry in the returned reference. A source and proof with similar names can still contain different content.

Version the revised file rather than allowing several incompatible finals to circulate. Keep the release tied to the accepted export, dimensions and artwork identity. If a later source edit occurs, identify whether a new export and approval are required.

There is a tradeoff between preserving full editability and simplifying a production exchange. The answer is usually a controlled source plus a checked reference, with any required production export identified. It is not a blanket instruction to flatten everything or insist that every buyer owns specialist design software.

Close a receiving-side dependency record

A folder full of attachments can still leave the receiver unsure which image belongs to the released artwork. Make a short dependency record from the exact source being handed over. Identify the source revision, linked assets, font status and the export used as the appearance reference. The point is to connect these items, not to collect every file the designer has ever used.

Adobe's Illustrator packaging documentation describes link collection, relinking and a report covering used or missing fonts and image details. It also directs users to check permission before copying fonts. That is a useful software route, with its own scope; it does not establish that a particular received folder is complete or that its assets are authorized.

Received item Receiver records Open issue to return
Source revision Exact document received Wrong or ambiguous revision
Linked image Identified file and intended use Missing, changed or uncertain link
Typography Available reproduction route Substitution or handoff restriction
Reference export Exact file used for comparison Appearance differs from source

Ask the receiving designer to open the transferred package through the intended workflow and report meaningful missing or changed content. A preview image cached in a source file should not be treated as confirmation that the editable asset is available. Conversely, the receiver should not silently replace an unavailable photograph with something similar just to make the document open cleanly.

If the supplied route cannot retain editability, discuss a checked production export and its limits. Preserve the editable original with its owner. An outlined-text export may answer a reproduction question while leaving future editing or permission questions unresolved. Those are acceptable distinctions when they are explicit.

Close each returned issue against a named revised export. Record who accepted a changed image or typography, and check the affected artwork at final dimensions. Repacking the folder does not itself approve a visible change. If the same dependency feeds several variants, identify the affected variants rather than assuming that correcting the first preview corrects the whole range.

For the supply-format discussion, see the relevant custom-label format with the defined application and review scope.

Send the source/export revision, dependency list, unresolved links or typography, final dimensions and quantities in a file-handoff enquiry. These let the receiver identify missing content and confirm what needs a new export.
